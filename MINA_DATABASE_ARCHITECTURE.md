## 1. Overview

### Design Constraints (from architecture)

- One database, separate tables
- Files in object storage; database stores metadata and links
- US-first; state mandatory on user profile
- Guest data: browser session only — **no guest tables**
- User data never used for AI training
- Export, delete, and audit trail required day one
- Auth: email + password, Google sign-in

### Layer Model

| Layer | Contents |
|-------|----------|
| 0 | Core platform (users, profiles, consents, preferences, subscriptions) |
| 1 | Shared entities (debt_situations, collectors, creditors) |
| 2 | Shared intelligence (debt/stress/recovery profiles, memory) |
| 3 | Cross-cutting (legal_attention_events) |
| 4 | Feature modules (each with primary + history tables) |
| 5 | Read models (timeline, dashboard) |
| — | Memory Service (candidates → entries pipeline) |
| — | System catalogs (letter templates, legal resources) |
| — | Compliance (audit, export, deletion) |

## 2. Conventions

### Primary Keys

- All tables use `id` as primary key
- Type: **UUID**
- Generated by application or database default

### Foreign Keys

- Column naming: `{referenced_table_singular}_id` (e.g., `user_id`, `debt_situation_id`)
- ON DELETE behavior documented per relationship
- All user-owned rows include `user_id` for RLS

### Timestamps

| Column | Usage |
|--------|-------|
| `created_at` | Row creation (required on all tables) |
| `updated_at` | Last modification (mutable tables) |
| `occurred_at` | Event/history timestamp (when distinct from created_at) |
| `resolved_at` | Resolution timestamp (alerts, legal attention) |
| `deleted_at` | Not used — architecture specifies permanent delete for documents; archive status used for recovery plans |

### Enumerations

Stored as **text** with documented allowed values (implementation may use Postgres enums later).

### JSON Columns

Used for structured payloads where architecture defines flexible/feature-specific schemas: `event_payload`, card outputs, checklists, recommended steps.

## 14. Object Storage Buckets

Files stored in object storage. Database stores metadata and `storage_path` references only.

| Bucket | Owner Feature | Contents | Access |
|--------|---------------|----------|--------|
| `documents` | Document Analysis | Original uploads (PDF, JPG, PNG, HEIC, WEBP). Max 25 MB, 50 pages | User-private. Deleted when user deletes document |
| `letter_exports` | Letter Generator | Exported PDF and DOCX files | User-private |
| `data_exports` | Compliance | Generated "export my data" packages | User-private. Expire after download window (implementation TBD) |
| `case_packets` | Legal Support | Case packet PDF exports (V3/deferred) | User-private. In-app view uses DB in V2 |

### Storage Path Convention

```
{bucket}/{user_id}/{feature}/{record_id}/{filename}
```

Example: `documents/{user_id}/document_uploads/{upload_id}/letter.pdf`

### Bucket Rules

- No public buckets for user content
- User can view and download their own originals (documents)
- User controls deletion — documents permanently deleted including storage object
- Letter exports retained until user deletes letter request or account
- Account deletion removes all user objects across all buckets

## 16. Row Level Security Requirements

RLS enabled on **all tables** except none — system catalogs use read-only policies.

### Policy Model

| Role | Access |
|------|--------|
| **Authenticated user** | SELECT, INSERT, UPDATE, DELETE on own rows (`user_id = auth.uid()`) |
| **Service role** | Full access for Memory Service, Timeline indexer, Dashboard sync, account deletion, export generation |
| **Anonymous** | No database access (guest data is session storage only) |

### Table-Specific RLS Rules

| Table Group | SELECT | INSERT | UPDATE | DELETE | Notes |
|-------------|--------|--------|--------|--------|-------|
| Core platform | Own | Own | Own | Own | User manages own profile, consents, preferences |
| Shared entities | Own | Own | Own | Own | User manages own debt situations, collectors, creditors |
| Shared intelligence | Own | Own | Own | Own | User can edit Memory entries (corrections) |
| Memory candidates | Own | Own (via feature) | Service role only | — | Status transitions by Memory Service |
| memory_history | Own | Service + system | — | — | Append-only for users |
| Feature modules | Own | Own | Own | Own | User owns all feature data |
| Feature histories | Own | Own + service | — | — | Append-only; no user UPDATE |
| timeline_events | Own | Service role only | — | — | Indexer writes; user reads |
| dashboard_snapshots | Own | Service role only | Service role only | — | Sync job writes |
| dashboard_recommendations | Own | Service role | Own (dismiss/snooze) | — | User can dismiss/snooze non-legal |
| dashboard_alerts | Own | Service role | Own (dismiss) | — | Legal alerts: dismiss recorded, not snoozed |
| letter_templates | All authenticated | — | — | — | Read-only catalog |
| legal_support_resources | All authenticated | — | — | — | Read-only catalog |
| audit_events | Own | Service role | — | — | User can read own audit trail |
| data_export_requests | Own | Own | — | — | User initiates export |
| account_deletion_requests | Own | Own | — | — | User initiates deletion |

### Premium Tier Enforcement

Application layer checks `subscriptions.tier` before writes to premium features:

- Live Call Assistant sessions
- Letter Generator requests
- Decision Shield reviews
- Recovery Planner plans
- Unlimited document uploads

Database may add RLS helper functions later; V2 gating is application-enforced per architecture.

### Memory Service RLS

- Features INSERT into `memory_candidates` as authenticated user
- Memory Service (service role) UPDATEs candidate status and INSERTs into `memory_entries`, `memory_entry_sources`, `memory_history`
- User UPDATE on `memory_entries` for corrections (sets `user_corrected = true`, may supersede)

### Cascade Delete

`users` ON DELETE CASCADE to all user-owned tables. Account deletion request triggers:

1. Object storage cleanup
2. User row deletion (cascades all FKs)
3. Auth provider user removal (application layer)
